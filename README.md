# DeepTunisia

**deeptunisia.org** — an open-source public-interest research project documenting Tunisia's political, institutional, economic and historical power structures through verifiable evidence, 1956–2026.

It is **not** a website exposing a deep state. That framing presupposes its own conclusion, and a project that begins from a conclusion cannot be trusted to test it. The narrower question is answerable: which institutions, individuals and economic groups retain influence when the formal regime changes, and which relationships are genuinely continuous rather than reconstructed after each rupture. On the evidence page you can watch the data support that question and refuse it — two of six hypotheses currently come out badly, including the strong version of the deep state thesis.

The website is a window. **The knowledge graph is the project.**

## Run it

```bash
npm install
npm run dev          # builds the graph, then starts the dev server on :5173
npm start            # atlas on :5173 AND the Agora API on :5200, one command
npm run build        # validates, exports, and produces a static site in build/
npm run test         # 12 suites: graph assertions, matcher precision, post markup,
                     #   feed separation, byte-fidelity, community layer and API
npm run check        # svelte-check — must be 0 errors, 0 warnings
npm run smoke        # real browser, both themes, desktop AND phone — needs a dev server
npm run feed         # fetch news headlines into feed/ (also runs every 4h in CI)
npm run data         # rebuild the graph and public exports only
```

The atlas itself needs no server, no database, no API and no accounts — the
static site ships as files. The discussion layer (Agora) is separate: a
community API with a D1 database and pseudonymous identity, **staged behind
`AGORA_OPEN` and not yet public**. `npm start` runs both so the Agora tab is
reachable during development; a reader on deeptunisia.org never touches it.

The complete graph is <!--stat:graphKB-->4410<!--/stat--> KB as the internal
bundle, and the public exports (dataset, CSVs, geographic layers, changelog)
ship at <!--stat:shippedKB-->7890<!--/stat--> KB — both are computed by the
build, and `npm run test` fails if the README ever disagrees with them.

## The views

The in-product orientation page — each view's one-sentence answer, when to use
it, and the four-basis legend — lives at **/guide** and is the maintained copy;
this table mirrors it and must be kept in step.

| View | What it answers |
| --- | --- |
| **Chronicle** | Who held which post, when, drawn to scale. Bar length is tenure, so continuity is visible without reading. |
| **Now** | Who holds which office today — split by how recently each was verified, and measured against that office's historical median tenure. |
| **Network** | Who connects to whom. Fixed lane per layer, so cross-layer bridges are literally the edges that cross lanes. |
| **Atlas** | Everything at once: structure per era as small multiples, a survival matrix of people against eras, an institution-crossing matrix, and median tenure per office. |
| **Rankings** | Five separate structural indices with reader-adjustable weights. Deliberately no single power score. |
| **Map / World** | Tunisian governorates and strategic assets with sourced coordinates; Tunisia's place among states and international organisations. |
| **Investigate** | Structured queries over the graph. *Computed by traversal, never generated by a language model.* |
| **Evidence** | Hypotheses with falsifiers, open questions, unresolved source contradictions, every citation. |
| **Agora** | Discussion, proposed changes and reports — *staged, not public*. Everything here is unreviewed public text, deliberately rendered in a register no sourced claim ever wears. The news **Feed** lives under it. |

Plus `/methodology`, `/corrections` (every change to the dataset, generated from version control), `/about` (governance, funding transparency, honest status) and `/data` (the full graph, downloadable under **CC BY 4.0** — the code is MIT; see `LICENSE` and `data/LICENSE`).

## The rule that matters most

**An inference is never allowed to become a fact.** Every claim is filed under one of four bases, and they never render identically:

| Basis | Meaning | Rendering |
| --- | --- | --- |
| `documented` | An official record, decree or gazette entry states it | Solid |
| `reported` | Credible publications report it, with attribution | Dashed |
| `inferred` | Nobody states it; reasoned from documented structure | Dotted |
| `unsubstantiated` | Circulates without reliable evidence | Dot-dash, off by default |

The evidence dial sets the floor. Raising it to documented-only visibly dissolves much of the network, which is the most informative interaction on the site.

**Unsubstantiated claims are recorded, not deleted.** Deleting a widely-held claim does not make it go away; it means the map cannot show anyone *why* the popular account is wrong. Several on record here are contradicted by this project's own data — the claim that the army secretly governs Tunisia, for instance, sits next to the record of the tri-service command going unfilled for two decades.

Two obligations are enforced by the build, as hard failures:
- An `inferred` claim must state its **reasoning** and what would **falsify** it.
- A grade C/D claim must name **who is making it**.

There is no way to slip an unattributed insinuation into this dataset.

## How the data is modelled

```
data/
  sources.yaml        every citation, tiered 1-5, with archive lookups
  eras.yaml           seven periods, each with an explicit thesis
  institutions.yaml   the command tree, layered, incl. foreign actors
  roles.yaml          canonical offices + the published authority weight table
  people.yaml         names in three scripts, aliases, trajectories
  positions.yaml      (person x role x span) — the join that makes time-travel work
  relationships.yaml  typed, dated, based edges
  events.yaml         with competing framings and source disputes side by side
  questions.yaml      what is still unknown
  hypotheses.yaml     falsifiable claims with honest verdicts
```

Six decisions carry most of the weight:

**Positions are the join table.** A `Position` is `(role, holder, start, end)`. You cannot ask "who held power in 1994" from a list of people, only from a set of intervals.

**Dates are ranges, not points.** Four fields — earliest/latest start, earliest/latest end — plus a status (`ended`, `ongoing`, `last-verified`, `unknown`). The Chronicle draws the documented core solid and the uncertain envelope hatched. Grammar: `2018-06-01`, `2018-06`, `2018`, `~2017`, `<=2018-06`, `ongoing`, `verified:2025-12`, `?`.

**Basis describes the claim, not its dates.** A position bundles two separable claims — "X held this post" and "between these dates" — which routinely have different standing. A security chief whose office is well reported but whose start date nobody published is a *reported* officeholding with an *inferred* span. `datesInferred` is a separate flag so imprecise dating never looks like speculation.

**Successions are derived, not asserted.** Computed from the position records, so a hole shows up as a hole: currently **<!--stat:successionGaps-->43<!--/stat--> gaps** and **<!--stat:successionOverlaps-->2<!--/stat--> overlapping tenures**, all published.

**Change is a record too.** The dataset is plain text under version control, so every factual change is a dated, attributable diff. `/corrections` publishes that history — generated, not curated, so nobody decides which changes are flattering enough to appear.

**Disagreement is a record, not a problem to resolve.** When sources conflict, both are stored with who holds each and whether it was adopted. Currently **<!--stat:contradictions-->62<!--/stat--> recorded contradictions**, including one where five different sentence lengths circulated across outlets for overlapping proceedings and the dataset declines to guess how many cases there were.

## The news feed is not the dataset

`/feed` shows headlines other people published. **It is not DeepTunisia data**, and the separation is structural rather than a disclaimer:

- The archive lives in `feed/`, never `data/`. The graph build does not read it.
- Items carry **no basis and no confidence field**. That is not an omission to fix later — giving an unread headline the vocabulary of an assessed claim would assert a judgement nobody made.
- Nothing in it is counted in any statistic this project publishes.
- Only headline, link, outlet, timestamp and language are stored. No body text.
- `npm run test` asserts all of the above, including that the fetcher touches exactly one path and never disables TLS verification.

Names in headlines are linked to graph entities by **deterministic string matching, never a language model**, so every link is explainable by the surface form that produced it. A highlight means the headline contains a name the graph knows — not that the article is about that person, and not that any of it is true.

Surname-only matches are refused. The matcher can only measure distinctiveness against the few hundred people recorded here, and Tunisia has around twelve million: on real headlines that rule linked a 2012 interim finance minister to a story about solar batteries. `scripts/test-match.ts` pins the decision with those fixtures.

## Adding to the dataset

1. Add the citation to `data/sources.yaml` first, with a tier. Tier 1 is a decree or gazette entry; tier 5 is a lead that needs corroborating and is never sufficient alone.
2. Add the claim, referencing that source id.
3. Grade it honestly. Single-outlet assessment → `C` + `attributed_to`. Reasoned estimate → `basis: inferred` + `reasoning` + `falsifiable_by`.
4. Run `npm run data`, then `npm run test`. Fix what they reject.

Prefer gazette appointment decrees above everything else: they give exact dates, which is what the whole timeline depends on.

## Everyone gets the same standard

Bourguiba, Ben Ali, Saied, Ennahda, the opposition, the military, the police, the business families, the unions, the EU, France, Italy, Algeria, the US, Russia, the World Bank and international NGOs are all in the graph under identical rules. An atlas of Tunisian power containing only Tunisians reads as an indictment of Tunisians.

This is not neutrality for its own sake — it is the project's only real protection. Credibility that depends on people agreeing with the conclusions collapses the moment they don't. Credibility that depends on the evidence being accessible and reproducible does not.

## Known limits

- **Only <!--stat:reviewed-->27<!--/stat--> of <!--stat:reviewable-->884<!--/stat--> records have had independent human review.** The stated architecture is that machines propose and humans verify; almost nothing has been through a second pair of eyes. The real number is published on `/about` because that is the only way the commitment means anything.
- **Defence intelligence (ANRSD) has no primary sourcing at all** — statute, appointment date, current status all unestablished. Largest hole in the security map.
- **Pre-2011 police chronology is the weakest area**, resting largely on secondary sources.
- **The 2014–2019 police succession does not fit its endpoints.** Three reported tenures cannot fit between two firmly dated ones; recorded as an unresolved contradiction rather than smoothed over.
- **`<=` bounds use an 8-year window.** Stated modelling assumption, not a fact.
- **UI is translated for chrome only.** Arabic, French and English navigation, controls and labels, with RTL. Entity names are trilingual in the data and all three are searchable. Long-form analytical prose is deliberately *not* machine-translated — a machine-translated epistemology page would undermine the point.
- **<!--stat:needsPrimarySource-->229<!--/stat--> records await a primary source.** Listed in full on `/evidence`.
- **Human review is not merely thin, it is aimed at the wrong records.** Broken out by risk, all of it has landed on the best-evidenced claims: **0 of the unsubstantiated claims, 0 of the attributed ones and 0 of the inferences** have been through a second pair of eyes. The breakdown is on `/about`.
- **<!--stat:sourcesUncited-->35<!--/stat--> of <!--stat:sources-->1195<!--/stat--> sources back no claim.** Staged reading, kept in the file but excluded from the published count of <!--stat:sourcesCited-->1160<!--/stat--> — a bibliography entry that holds nothing up is not evidence.

## Deliberately not built yet

The ingestion pipeline (discovery → extraction → entity resolution → evidence attachment → contradiction detection → **human verification** → graph) is designed and the schema supports it: `review` provenance, `disputes`, alias-based entity resolution. It is not built, because the automatable parts are the easy parts and building volume before verification capacity exists would produce exactly the failure mode this project is meant to correct.

Same for the assisted research layer. When it comes, it must traverse this graph and cite records — never generate the answer.

## Editorial position

A high brokerage score means the dataset records someone connecting otherwise separate networks. It is not evidence of wrongdoing, coordination or hidden control.

A prison sentence is a documented fact. The allegations behind it and the criticism of the proceedings are contested; both framings are stored with attribution rather than adjudicated.

Wealth is not corruption. The dataset distinguishes established business families from politically created ones, because collapsing that distinction is the most common error in popular accounts — the Mabrouk fortune predates Ben Ali; a marriage brought one branch inside the presidential family; the same person was later imprisoned by the successor state. All three facts have to survive contact with each other.
